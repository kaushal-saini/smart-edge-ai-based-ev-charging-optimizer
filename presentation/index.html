01 // Problem Statement & Motivation

The Real-World EV Charging Dilemma

⚠️

Current Unmanaged Charging Challenges

  • Grid Overload & Power Spikes: Multiple EVs plugging in simultaneously exceed local transformer capacity.
  • High Peak-Tariff Costs: Charging during expensive peak-hour tariff schedules drives up operational expenditure.
  • No Predictive Analytics: Station operators have zero forecast of incoming vehicles or remaining session durations.
  • Unbalanced Bay Utilization: First-come-first-served allocation creates bottleneck delays and uneven charger wear.
💡

Our Edge AI + IoT Solution

  • Autonomous Edge Intelligence: Microcontroller executes lightweight ML locally for zero-latency decisions.
  • Dynamic Power Throttling: Time-sliced PWM duty-cycling limits load without tripping circuit breakers.
  • Cost-Aware Off-Peak Scheduling: Deferral logic delays non-urgent charging during peak tariff periods.
  • End-to-End Cloud Observability: Full real-time telemetry, remote RPC overrides, and instant alarms via ThingsBoard.

Wokwi Simulation Hardware Wiring

Component ESP32 GPIO Function & Range
Voltage Potentiometer GPIO 34 Simulates supply voltage (0 – 250 V)

DHT22 Sensor GPIO 15 Charger/ambient temperature monitoring
Plug-In Push Button GPIO 32 Triggers FREE → CHARGING transition
Plug-Out Push Button GPIO 33 Triggers CHARGING → FREE transition
Status LEDs (G / Y / R) 18 / 19 / 21 Green: Free | Yellow: Charging | Red: Fault
Power Relay Module GPIO 26 Switches charging power (PWM duty-cycle)
⚡

Key Hardware Engineering Features

  • Hardware Input Debouncing: 200ms software lockout prevents spurious contact bounce on plug-in/out triggers.
  • Safe Sensor Scaling: Dual linear mapping function converts ADC values (0–4095) with zero floating-point overflow.
  • Trapezoidal Energy Accumulator: Real-time numerical integration computes cumulative kilowatt-hours ($Wh = \sum P \cdot \Delta t$).
  • PWM Relay Throttling: Modulates charging power over a 2000ms duty-cycle window when throttled to 50% or 70%.
04 // Edge Artificial Intelligence

Lightweight Embedded On-Device Inference

📊

1. Feature Extraction

Constructed every 5s from onboard sensors and clock:

  • hourOfDay (0–23)
  • dayOfWeek (0–6)
  • bayOccupied (0/1)
  • recentAvgCurrent (10-sample rolling avg)
  • sessionElapsedMin (active duration)
  • historicalArrivalRate (commute profile)
🎯

2. Arrival Probability

Logistic Regression:

P(arrival) = σ(∑ wixi + b)

Predicts probability ($0.0 \to 1.0$) of a new EV arriving in the next 30 minutes. Trained with scikit-learn, evaluated at 72.6% accuracy (0.767 ROC-AUC).

⏱️

3. Session Duration

Decision Tree Regressor:

Max Depth = 5

Predicts remaining charging time in minutes based on battery capacity, initial arrival SoC, and rolling current rate. Fully converted to static C header model.h.

💡 Zero Cloud Overhead: Inference runs in under 5 ms on the ESP32 CPU with zero TensorFlow runtime overhead, taking less than 14% RAM!
05 // Autonomous Control Logic

Local Allocation & Grid Overload Management

CONDITION 1
Overcurrent Detection: current > overloadCurrentA (16A)
→ Decision: THROTTLE (50%) | Red LED ON | Critical Overload Alarm
CONDITION 2
Station Power Exceeded: power > maxStationLoadW (6000W)
→ If predictedDurationMin > 10: THROTTLE (70%)
→ Else: ALLOW (100%) (Priority to finish nearly full EVs)
CONDITION 3
Peak-Tariff Hours: 18:00 – 22:00 & Bay is FREE
→ If arrivalProb < threshold: DEFER (0%) (Avoid unnecessary standby draw)
CONDITION 4
Normal Operation:
→ Decision: ALLOW (100%) | Full charging speed
⚡

Duty-Cycle Modulation Engine

To implement throttling without complex AC dimming hardware, firmware utilizes dynamic time-slicing over a 2000ms window:

ON (1400ms)
OFF (600ms)
70% Throttle Mode: Staggers peak energy demand while keeping EV battery charging active.
Manual Operator Override: Cloud operator can remotely override charger state (setRelayState or setThrottle) via ThingsBoard RPC, pausing automated optimization.

07 // Professional Development

Internship Learnings & Technical Takeaways

🚀

Core Technical Skills Gained

  • Embedded C++ on ESP32: Mastered modular firmware design (headers, separation of concerns, non-blocking asynchronous timing with millis()).
  • TinyML & Edge AI Deployment: Learned how to train machine learning models in Python (scikit-learn) and export them into standalone C arrays and decision tree algorithms for microcontrollers.
  • IoT Messaging & Cloud Telemetry: Built robust MQTT client communication with PubSubClient, handling reconnects, JSON serialization, and RPC request dispatching.
  • Cloud Architecture: Configured ThingsBoard dashboards, device credentials, shared attributes, and automated alarm rule chains.
🏆

Key Engineering Insights

  • Edge vs Cloud Compute: Running inference locally ensures continuous safety and load balancing even during network drops.
  • Constraint Optimization: Fitting ML models and MQTT buffers within ESP32 RAM requires zero-copy buffers and static memory allocation.
  • Simulation Fidelity: Using Wokwi alongside PlatformIO provides a rapid development feedback loop for hardware verification.
  • Industry Impact: Solves real electric vehicle infrastructure challenges for green energy and smart cities.
